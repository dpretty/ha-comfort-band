# Comfort Band

Per-room HVAC band-control for Home Assistant. Heats below a low threshold, cools above a high threshold, idles in between — giving heat pumps and mini-splits margin instead of fighting to hold a single setpoint.

**v0.9.2** makes the room-temperature sensor swappable post-add via the existing zone OptionsFlow. Swapping flushes the zone's sample buffer so the slope estimator restarts cleanly; schedules and learning state are preserved. Pairs with v0.9.1's diagnostics: if `std_dev_idle` sits near 0, your sensor is too coarse — this OptionsFlow lets you swap to a finer one in one click.

**v0.9.1** adds per-segment diagnostics to `sensor.{zone}_thermal_slope` — `sample_count_*`, `std_dev_*` and `method_*` attributes let users spot when a slope estimate is unreliable due to a low-resolution sensor sitting on the same quantized value for hours. The slope reports 0 in that regime not because the room is stable but because the sensor can't see the drift. No behaviour change.

**v0.9.0** teaches the v0.8 MPC to see upcoming schedule transitions. The coordinator computes the per-minute `(low, high)` band the schedule resolves to over `mpc_horizon_minutes`, and the cost function scores each candidate action against the band that will be active at end-of-horizon (not the band frozen at the snapshot). A morning band-rise from `(16, 19)` → `(20, 22)` at 07:00 now triggers pre-heat well before 07:00 instead of being chased reactively. Same release adds an **idle-preference tie-break**: when `idle` achieves full-horizon in-band coverage, it wins over heat / cool even if a recovery action lands closer to band midpoint — stops MPC burning compressor cycles on margin gains the room already has. Default `mpc_horizon_minutes` bumped 20 → 60; existing zones keep their explicit value (bump manually toward 60 to unlock the full pre-heat window). **Behaviour change for existing `mpc_enabled` users:** steady-state operation will see fewer heat/cool cycles than v0.8.1 because idle-preference now wins ties.

**v0.8.1** relaxes the v0.8.0 MPC cold-start gate so heat-only and cool-only zones activate MPC after the first idle + matching-recovery segment accumulates (was: required all three). Per-refresh safety bail-out defers to the v0.7 predictor when the room genuinely needs the missing direction. No behaviour change for fully-equipped zones.

**v0.8.0** adds a model-predictive controller as the third decision layer in the stack. Each refresh, MPC enumerates a small action space (`idle`, `heat → band's high edge`, `cool → band's low edge`), simulates each forward over `mpc_horizon_minutes` (default 20 min) using the v0.6 thermal slopes, and picks the action that maximises projected time-in-band. Behind a new opt-in `switch.{zone}_mpc_enabled` (default OFF) layered on top of `learning_enabled`; cold-start gated by `binary_sensor.{zone}_mpc_ready` (True once enough samples in idle / heat / cool segments have accumulated). v0.7's predictor remains the fallback during warm-up. v0.8 also captures the climate's `fan_mode` attribute in each sample (recorded but unused — v0.9 will partition slopes by `(action, fan_mode)` and grow MPC's action space to include fan-mode candidates). Builds on the v0.1 core (per-zone entities, asymmetric-deadband hysteresis, profile-driven schedules), v0.2 schedule WS subscription, v0.3 profile CRUD, v0.4 apparent-temperature support, v0.5 cross-mode min-cycle dwell, v0.6 learned thermal-slope estimator, and v0.7 passive drift acceptance.

The Lovelace card lives in a separate repo — install [dpretty/ha-comfort-band-card](https://github.com/dpretty/ha-comfort-band-card) via HACS as a Dashboard Custom Repository.

Defaults to **shadow mode** per zone (`switch.{zone}_enabled = off`) so you can verify decisions side-by-side with your existing setup before cutting over.
